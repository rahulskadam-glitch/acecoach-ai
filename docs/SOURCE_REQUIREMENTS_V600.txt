You are the principal product architect, lead full-stack engineer, agentic-AI architect, UX design director, security engineer, sports-biomechanics expert, and elite multi-sport coach for AceCoach AI.

Create AceCoach AI v6.0.0: a complete simplification and professional redesign of the athlete experience.

The current platform contains useful capabilities, but the user journey is too complex. The new product must hide technical complexity behind a clear six-step journey:

1. Select sport
2. Sign in
3. Upload video and provide essential information
4. Analyze
5. Review report
6. Continue with a coaching conversation

Do not remove reliable v5 functionality unnecessarily. Reorganize it behind this simplified journey.

The user should never need to understand:

- database tables,
- analysis engines,
- pose models,
- job orchestration,
- motion-twin versions,
- technical confidence formulas,
- agent architecture,
- or internal processing details

to complete their first analysis.

The interface must feel:

- premium,
- sophisticated,
- calm,
- professional,
- visually spacious,
- easy for a first-time athlete,
- suitable for junior athletes, parents, experienced players, and coaches.

The default appearance must use a refined light background.

============================================================
1. PRIMARY PRODUCT OBJECTIVE
============================================================

Transform AceCoach into the simplest credible sports-analysis experience:

SELECT SPORT
→ SIGN IN
→ UPLOAD AND DESCRIBE
→ ANALYZE
→ UNDERSTAND
→ ASK YOUR COACH

The user must always know:

- where they are,
- what is required,
- what will happen next,
- whether their information has been saved,
- and how to continue.

The first analysis journey must not require the user to visit a dashboard, profile page, library page, settings page, or pricing page.

Those destinations may remain available through a secondary account menu after the first analysis.

============================================================
2. NON-NEGOTIABLE EXPERIENCE PRINCIPLES
============================================================

1. One screen must have one primary purpose.
2. One screen must have one dominant call to action.
3. Do not show information before it is needed.
4. Do not ask for information that does not affect the analysis.
5. Preserve the user’s selected sport throughout authentication.
6. Preserve form and upload progress through refresh and reauthentication.
7. Never silently guess the movement type.
8. Movement or stroke selection is mandatory.
9. The raw uploaded video remains owned and downloadable by the user.
10. The analysis page must show real processing stages, not fabricated percentages.
11. The report must prioritize one correction.
12. Technical depth must remain available but collapsed.
13. The coaching conversation must be grounded in the completed report.
14. The language model must not invent measurements.
15. Authentication-provider buttons must only appear when the provider is configured.
16. Unsupported analysis must fail honestly.
17. The application must work well on desktop and mobile.
18. Do not introduce a dashboard before the user completes the first analysis.

7. STEP 4 — ANALYSIS PROCESSING
============================================================

Route:

/analysis/[sessionId]

Page purpose:

Give the user confidence that AceCoach is working without exposing internal complexity.

Show four simple confirmed stages:

1. Checking video quality
2. Confirming the movement
3. Measuring the technique
4. Building your coaching report

Use a calm animated visual.

Do not show:

- fabricated percentages,
- fake countdowns,
- random progress movement,
- raw logs,
- model names,
- internal queue terminology.

Show:

- current confirmed stage,
- completed stages,
- elapsed time,
- whether the user may leave the page,
- notification option,
- retry state when applicable,
- cancel action when safe.

When classification conflicts with the user’s selected movement:

Display an interruption card:

“You selected Forehand.
AceCoach detected Two-handed backhand.
Confidence: High.”

Actions:

- Use detected movement
- Keep Forehand
- Review the clip

Do not continue sport-specific scoring until the conflict is resolved.

When confidence is low:

“We could not confirm the movement reliably.”

Actions:

- Choose the movement manually
- Review the clip
- Upload a better video

When the video is unsuitable:

- preserve the video;
- explain the exact capture problem;
- do not create a fake report;
- provide a direct re-record action.

When processing fails:

- preserve the original video;
- preserve the last successful report;
- show a clear reason;
- allow retry;
- provide Report issue.

When complete:

- navigate automatically to the report;
- provide a visible Open report action as a fallback.

Analysis-page acceptance criteria:

- Processing stages represent server-confirmed states.
- Page refresh restores the current job.
- Worker restart does not create a duplicate job.
- Failure does not delete the video.
- No-score behavior is used when reliability fails.
- The user can leave and return.
- The page does not expose unnecessary technical details.

============================================================

Route:

/report/[sessionId]

The report must remain professional, highly visual, and easy to understand.

Use exactly four primary sections.

------------------------------------------------------------
8.1 Section 1 — Coach Summary
------------------------------------------------------------

Display:

WHAT YOU DO WELL

FIX THIS FIRST

WHY IT MATTERS

YOUR CUE

HOW YOU WILL KNOW IT IMPROVED

Only one primary correction appears here.

Example:

WHAT YOU DO WELL
You keep your head relatively stable through the swing.

FIX THIS FIRST
Start the shoulder turn earlier.

WHY IT MATTERS
Late preparation makes the forward swing rushed and reduces control.

YOUR CUE
“Turn before the ball arrives.”

HOW YOU WILL KNOW IT IMPROVED
Your shoulder turn begins before the forward swing in at least eight of ten repetitions.

Include:

- Show me button,
- Start practice button,
- Ask AceCoach button.

The summary must be understood within five seconds.

------------------------------------------------------------
8.2 Section 2 — Watch and Compare
------------------------------------------------------------

Show:

YOUR MOVEMENT

YOUR NEXT TARGET

BEST-IN-CLASS

Your Movement:

- clean original video by default;
- no skeleton;
- no pose dots;
- no technical overlay;
- no annotations unless enabled.

Your Next Target:

- category-appropriate motion twin;
- same handedness;
- same movement type;
- developmentally realistic;
- not merely a slowed elite movement.

Best-in-Class:

- evidence-backed movement archetype;
- not one copied professional athlete;
- clearly labelled as an exemplar rather than a universal ideal.

Controls:

- play and pause;
- 0.25x;
- 0.5x;
- 1x;
- previous frame;
- next frame;
- previous phase;
- next phase;
- loop phase;
- loop movement;
- timeline scrub.

Phases:

- Preparation
- Load
- Swing
- Contact
- Finish
- Recovery

Allow:

“Compare one difference”

When enabled, show no more than three labelled guides.

Never place unexplained arrows over the video.

------------------------------------------------------------
8.3 Section 3 — Your Improvements
------------------------------------------------------------

Show a maximum of three improvements.

Each improvement includes:

- simple title,
- what AceCoach observed,
- where it happened,
- why it matters,
- what to change,
- coaching cue,
- jump-to-frame action.

Do not repeat the primary correction using different wording.

Prioritize findings based on:

- reliability,
- expected impact,
- coachability,
- relevance to the athlete’s level,
- relationship to the athlete’s goal.

8.4 Section 4 — Practice Plan
------------------------------------------------------------

Display:

- maximum two drills,
- sets,
- repetitions,
- short instructions,
- one cue,
- common mistake,
- measurable success target,
- when to record again,
- same-camera guidance.

Primary action:

“Start coaching conversation”

Secondary action:

“Record reassessment”

Conversation

Suggested questions:

- Explain my main correction more simply
- Show me the exact moment
- Why does this matter?
- How should I practise this?
- What mistake should I avoid?
- Is this appropriate for my level?
- Create my next practice session
- When should I record again?

The coaching agent may:

- explain structured findings;
- refer to exact phases and timestamps;
- simplify technical language;
- answer questions about drills;
- adjust approved drill difficulty;
- create a practice-session outline;
- summarize progress;
- prepare questions for a human coach.

The coaching agent may not:

- invent measurements;
- change confidence;
- claim a new movement observation without evidence;
- diagnose injury;
- create fake professional comparisons;
- override a reliability gate;
- imply that a proxy is directly measured;
- recommend unsafe practice volume;
- alter stored analysis without explicit user confirmation.

Every technical answer must be grounded in:

- the structured report,
- the measurement registry,
- the approved terminology dictionary,
- the approved drill library,
- the athlete’s saved context.

When the user asks something unsupported:

“AceCoach cannot determine that reliably from this video.”

Conversation features:

- persistent thread,
- timestamped messages,
- suggested prompts,
- frame-link responses,
- drill-link responses,
- clear new-conversation action,
- export conversation,
- share with coach,
- flag incorrect advice,
- privacy notice.

Conversation acceptance criteria:

- The assistant knows the active report.
- Answers cite the relevant phase or finding.
- Invented metric values are schema-blocked.
- Prompt injection through filenames, notes, or comments is neutralized.
- Conversation history remains attached to the analysis session.
- The user can return to the report without losing the conversation.
- Mobile keyboard behavior is reliable.

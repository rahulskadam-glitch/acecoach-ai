# AceCoach Tennis Knowledge Architecture v3.0.0

## Objective
AceCoach should behave like a rigorous coach who can see, compare, explain and prioritize—not like a pose-scoring app. The knowledge system therefore separates scientific evidence, visual observations, context, causal hypotheses, coaching decisions and presentation.

## Seven-layer model
1. **Research layer** — source registry with evidence tier and allowed use.
2. **Stroke model** — stroke families, variants, valid style differences, phase goals and non-negotiables.
3. **Observation layer** — only video-measurable/estimable variables with camera and confidence constraints.
4. **Benchmark layer** — player-success baseline first; matched cohort second; expert examples and research patterns next.
5. **Diagnostic layer** — candidates, recurrence, outcome linkage and causal graph.
6. **Coaching layer** — one primary correction, earned strengths, cue, constraint and success test.
7. **Visualization layer** — a four-beat visual story: cause → consequence → better window → clean replay.

## Non-negotiable product rules
- Never score evidence that is unavailable.
- Never invent a numerical biomechanical threshold because a professional player appears to use it.
- Never call technique variation a fault unless it conflicts with the player’s task or produces a repeatable performance problem.
- Never infer injury or diagnose pain.
- Never let the LLM generate measurements. Language is downstream of structured evidence.
- Prefer one high-leverage correction over a long checklist.
- Surface at least one genuine strength when supported by evidence.

## What makes the coaching feel elite
A world-class explanation answers five questions: **What happened? Where in the stroke did it start? Why did it matter for this ball? What should the player feel/do next? How will we know it improved?**

## Benchmark strategy
The system must not compare a 12-year-old beginner hitting a defensive open-stance forehand with an ATP attacking forehand. Every comparison should carry a context-match score. When the player has enough data, their own successful comparable strokes are the highest-value reference.

## Visual design
Player mode should feel cinematic and obvious. Pause only at the causal moment. Use motion paths, spacing bubbles and ghost windows to show a range. Then show the downstream consequence at contact/ball flight. Finally replay the stroke clean. Coach mode may expose angles, phase timings and sequence traces.
